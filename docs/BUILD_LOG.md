## ISS-001 — Repository scaffold & toolchain (2026-08-23)
### What was done
- Created full package skeleton: `api/`, `engine/`, `pipeline/`, `workers/`, `db/` (incl. `db/migrations/`), `signatures/`, `tests/`.
- `pyproject.toml` with runtime deps (FastAPI, Pydantic v2 + pydantic-settings, Celery, SQLAlchemy 2.0 async, asyncpg, Alembic, Playwright, boto3, structlog) and dev deps (ruff, mypy with pydantic plugin, pytest + pytest-asyncio).
- `Makefile` targets: `install lint format typecheck test db-upgrade db-downgrade run-api run-worker compose-up compose-down signatures-load`.
- `.env.example` covering DB / Redis / S3 / scan-engine limits / API settings; `.gitignore`; git repo initialized; initial commit.
### Design decisions / deviations
- pip + venv instead of uv (uv not present on the machine); Makefile workflow identical either way.
- mypy uses `pydantic.mypy` plugin (`init_typed=false`) so pydantic-settings models validate from env without false "missing argument" errors.
- Ruff per-file-ignore for autogenerated Alembic version files (long `sa.Column` lines are standard there).
### Limitations & known gaps
- Playwright chromium browser not yet downloaded in this environment (`make install` does it); no engine code depends on it until M1.
- No CI pipeline yet (planned as part of ISS-027/ISS-029 hardening).
### How to verify
- `make lint && make test` pass; `python -c "import api, engine, pipeline, workers, db"` succeeds.

## ISS-002 — Local dev environment (Docker Compose) (2026-08-23)
### What was done
- `docker-compose.yml` with postgres:15-alpine, redis:7-alpine, minio + a `minio-init` one-shot job that creates the artifacts bucket idempotently.
- Healthchecks on all three services; named volumes (`pgdata`, `redisdata`, `miniodata`) for persistence; env vars aligned with `.env.example` defaults.
- Brought the stack up and verified: all services healthy, bucket `authscope-artifacts` created, migrations ran against it.
### Design decisions / deviations
- MinIO console exposed on :9001 for dev convenience only.
- `minio-init` runs `mc mb --ignore-existing`, so restarts are safe.
### Limitations & known gaps
- No Elasticsearch/Kibana or Grafana/Prometheus yet — deferred to M4 (ISS-026).
- Credentials are dev-only plaintext defaults; production secrets handling is ISS-029 scope.
### How to verify
- `docker compose up -d --wait` → all containers `(healthy)`; `docker compose logs minio-init` shows "Bucket ready".

## ISS-003 — Configuration & settings module (2026-08-23)
### What was done
- `config.py`: grouped Pydantic-settings objects — `DatabaseSettings` (POSTGRES_* incl. `async_url`/`sync_url` properties), `S3Settings`, `ScanSettings` (45s timeout, captcha wait, RAM guard, retry flag), `ApiSettings` — aggregated in cached `get_settings()`.
- Missing required vars raise validation errors naming the field.
### Design decisions / deviations
- Each sub-group reads its own env prefix and its own `.env`, so components can also instantiate sub-groups standalone (e.g., workers loading only ScanSettings).
- Tests are hermetic: an autouse fixture chdirs to tmp_path so a developer's real `.env` never leaks into test results; `REDIS_URL` is a flat field on `Settings` (no prefix class needed).
### Limitations & known gaps
- No secret-manager integration (env/.env only) — production secret injection is ISS-029.
- Hot-reload of settings not supported (cached singleton); acceptable until workers need live signature reload (ISS-010 reloads signatures independently of settings).
### How to verify
- `pytest tests/test_config.py` → 5 tests: parsing, missing-var error, defaults, caching, bounds validation.

## ISS-004 — Database schema & migrations (2026-08-23)
### What was done
- `db/models.py`: all 10 tables — `users`, `api_keys` (SHA-256 key hash), `scans` (status enum values, options JSONB, composite index on `(normalized_url, created_at)` + status index), `auth_findings` (ARRAY(Text) flow, JSONB evidence), `security_findings`, `antibot_findings` (arrays for WAF/fingerprinting/cookies + difficulty_reasoning), `artifacts` (+trace_url beyond plan), `signatures` (category/name/versioned YAML JSONB/active), `webhooks`, `feedback`.
- Alembic async env wired to app settings (`db/migrations/env.py`), autogenerated initial migration, applied via `alembic upgrade head`; downgrade verified back to base.
- `db/seed.py` seeds a dev user + hashed API key (`DEV_API_KEY`, default `dev-key`), idempotent.
- Round-trip integration test against live Postgres: insert scan + every finding type + artifacts + signature, read back with eager loads, assert arrays/JSONB intact. Runs transactionally with rollback so it's repeatable; skips cleanly if Postgres is unreachable.
### Design decisions / deviations
- Added `scans.user_id`, `options`, `error_detail` and `antibot_findings.difficulty_reasoning` beyond the README schema — required by API auth (ISS-017+), cache/force logic (ISS-018), and score reasoning (ISS-016).
- Findings use one-to-one with unique FK on scans (README had plain FKs); prevents duplicate finding rows per scan.
- Round-trip test uses `selectinload` (async sessions forbid implicit lazy loads) and per-run unique names instead of commits, keeping the test side-effect free.
### Limitations & known gaps
- No ClickHouse/Timescale time-series store yet — diff feature (ISS-024) will need it; Postgres can bridge short-term via the `(normalized_url, created_at)` index.
- No pgvector column (Phase-3 AI feature, out of M0 scope).
- Test data cleanup relies on rollback; stale rows from pre-fix runs were manually cleared once.
### How to verify
- `alembic upgrade head && alembic downgrade base && alembic upgrade head` round-trips; `\dt` shows 11 tables (10 + alembic_version).
- `pytest tests/test_models_roundtrip.py -v` passes against compose Postgres.
- `python -m db.seed` prints seeded key; rerun prints "already seeded".
